# CBF-3DoF artifact audit

## Scope

This audit covers every regular file below `src/controllers/CBF-3DoF`.
The pre-audit tree contained 4,546 files totaling 6,328,091,084 bytes.
Python and Markdown files receive source or editorial review. JSON and CSV
files receive parse and schema checks. NPZ archives, PNG images, and SQLite
databases receive read-only content validation.

## Validation outputs

- `artifact_inventory.csv` contains one record per file, including artifact
  class, byte size, validation status, format metadata, and path-specific
  issues.
- `artifact_validation_summary.json` groups counts, issues, and JSON/CSV schema
  families.

## Issue ownership

- Importable controller implementation and associated tests: Task 3.
- Evaluation, tuning, and plotting programs: Task 4.
- Markdown structure, terminology, representative artifacts, and links: Task 5.
- JSON and CSV schema or prose findings: Task 6.
- NPZ, PNG, and SQLite findings: Task 7.

## Baseline findings

The first stable audit contains 4,552 files totaling 6,328,109,548 bytes. The
six files added to the original 4,546-file tree are the auditor package, its
test module, and the three audit outputs. The inventory contains:

- 4,081 NPZ archives;
- 244 CSV files across 27 header schemas;
- 126 JSON files across 16 object-key schemas;
- 48 PNG images;
- 36 Python files;
- 14 Markdown files;
- two SQLite databases;
- one `.gitignore` file.

All 4,552 files passed their applicable structural validation. The baseline
contains no parse errors, corrupt binary artifacts, SQLite integrity errors,
duplicate CSV headings, inconsistent CSV row widths, object-array warnings, or
other path-level findings. Historical differences among the JSON and CSV
schemas remain subject to the provenance review in Task 6; structural validity
does not by itself establish semantic consistency.

The filesystem and inventory path sets are identical. SHA-256 comparison found
no changes to pre-existing non-cache files during the read-only audit. The 28
`__pycache__` files generated by testing and compilation were removed before
the stable inventory was produced; they were transient interpreter output and
were absent from the original 4,546-file count.

## Importable implementation review

The eight files in `cbf_3dof/` and their six implementation-focused test
modules were reviewed for state and action ordering, units, reference frames,
barrier signs, actuator constraints, solver fallback behavior, diagnostic
fields, input validation, and public documentation. No behavioral defect was
identified. The existing tests exercise analytic and finite-difference barrier
behavior, boundary feasibility, solver backends, controller adaptation, and
manual scenarios.

`cbf_types.py` and `barriers.py` received documentation-only edits for public
data structures and scalar barrier helpers. `__init__.py`,
`closing_barriers.py`, `controller.py`, `diagnostics.py`, `port_dynamics.py`,
and `qp_filter.py` required no source changes. The reviewed test files required
no changes. The fallback in `qp_filter.py` remains explicitly non-certified:
on QP failure it returns the bounded nominal action and records the failure in
the result diagnostics.

## Workflow program review

The three evaluators, two tuning programs, four plotters, and six associated
test modules were reviewed for path construction, imports, argument parsing,
seed pairing, deterministic ordering, result schemas, error messages, and
terminology. All nine command-line programs resolve repository paths from
their source locations; no active machine-specific absolute path was found.
Each program's `--help` path completed without initiating an experiment.

Two statements were revised: the paired-evaluation module now describes the
sampling design directly, and the final-approach plotter identifies the
required field instead of using a relative schema label. No behavioral or
interface change was required. The other
seven executable files and all six reviewed test modules required no edits.

## Documentation review

All 14 Markdown files in the audited tree were reviewed. The root README and
the evaluation, tuning, plotting, closing-result, final-approach evaluation,
LQR-result, and trajectory-figure READMEs were revised to identify their
purpose, expected artifacts, and representative retained examples. The
remaining phase-specific READMEs and two technical result reports already
provide their required scope, provenance, or interpretation details.

Temporal labels were replaced where an explicit schema or dataset partition
was available. Statements about CBF behavior retain the distinction between
continuous-time inequalities, sampled rollouts, soft constraints, hard
constraints, and non-certified nominal fallback. No document claims a formal
sampled-data guarantee.

## JSON and CSV review

All 126 JSON files and 244 CSV files parse successfully. The JSON collection
contains 16 top-level object-key schemas, and the CSV collection contains 27
header schemas. The variants correspond to distinct artifact roles or recorded
evaluator generations: run configurations, aggregate tables, per-episode
tables, paired comparisons, tuning plans, tuning trials, selected gains, and
figure provenance. No schema was normalized across historical runs.

No assistant references, conversational drafting language, duplicate CSV
headers, inconsistent row widths, or encoding failures were found. A total of
118 structured-text files contain absolute Windows paths. These fields record
the model, normalization state, result directory, or study storage used by a
completed run; they are retained as historical provenance and are not consumed
as active defaults by the reviewed programs. No JSON or CSV artifact was
modified, so all recorded numeric values and provenance fields remain intact.

## NPZ, PNG, and SQLite review

All 4,081 NPZ archives opened without error and form 13 member-name schemas.
Non-finite numeric values occur in 2,613 archives. They are confined to
diagnostic fields for inactive constraint families, unavailable post-step
fields in earlier schemas, or QP-failure feasibility margins on steps where no
failure diagnosis applies. State, action, reward, time, and termination arrays
were not identified among the non-finite fields. These sentinel values are
retained because replacing them would change recorded experiment data.

All 48 PNG files decoded successfully and form 15 dimension/mode groups; every
image uses RGBA storage. Both Optuna SQLite databases return `ok` from
`PRAGMA integrity_check` and expose the expected study, trial, parameter,
value, attribute, heartbeat, version, and migration tables. SHA-256 comparison
confirmed that all 4,131 NPZ, PNG, and SQLite files match the baseline exactly.

The inventory fixed-point check identified and corrected an audit-tool issue:
self-records initially captured placeholder output sizes. The CLI now iterates
until the inventory and summary record their final on-disk sizes. The fix is
covered by `test_outputs_account_for_themselves_on_second_run`.

## Final verification

The focused CBF suite passes 123 tests with one skipped Windows symlink test.
The repository suite passes 580 tests with the same skip and two Gymnasium
warnings about intentionally unbounded observation-space limits. All CBF Python
files compile, all nine workflow `--help` commands exit successfully, every
local Markdown link resolves, and the final artifact audit reports no
path-level validation errors.

Verification also identified that `plot_constraint_and_control_diagnostics.py`
ignored `--help` and executed its plotting pipeline. Argument parsing now
occurs before output generation, and a regression test verifies that help
exits without invoking either plotting function. The retained figure-summary
content was restored; its missing terminal newline was normalized without
changing any JSON key or value.
